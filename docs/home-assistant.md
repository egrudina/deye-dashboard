# Home Assistant

Home Assistant reads `GET https://deye.grudina.info/api/ha` once a minute: one flat JSON with live values,
running kWh totals (for the Energy dashboard) and the plan (headline, next outage, battery forecast, schedule,
sun forecast). Nothing in HA talks to the inverter, Yasno or Solcast, so the bot and the Solcast quota are safe.

Files: `ha/deye.yaml` (the package: 51 sensors, 2 binary sensors), `ha/dashboard.yaml` (a ready dashboard).
Both are generated by `ha/make_package.py` (`uv run --with python-slugify python3 ha/make_package.py`).

## 1. Cloudflare: a service token for HA

HA cannot log in with an email, so it uses an Access service token. The Worker lets a service token read
only `/api/ha` (everything else answers 403).

1. Zero Trust → Access → Service credentials → Service Tokens → **Create Service Token**.
   Name it `home-assistant`, duration *Non-expiring* (or a year, and put a reminder in the calendar).
   Copy the **Client ID** and **Client Secret** now: the secret is shown only once.
2. Zero Trust → Access → Applications → the `deye` application → Policies → **Add a policy**:
   name `home-assistant`, Action **Service Auth**, Include → **Service Token** → `home-assistant`. Save.
   Keep the existing email policy as it is.
3. Check from any computer (should print JSON, not HTML):
   ```
   curl -s -H "CF-Access-Client-Id: <id>" -H "CF-Access-Client-Secret: <secret>" https://deye.grudina.info/api/ha | head -c 300
   ```

## 2. Home Assistant: the package

1. `secrets.yaml`:
   ```yaml
   deye_access_client_id: "<Client ID>.access"
   deye_access_client_secret: "<Client Secret>"
   ```
2. `configuration.yaml` (if packages are not enabled yet):
   ```yaml
   homeassistant:
     packages: !include_dir_named packages
   ```
3. Copy `ha/deye.yaml` to `<config>/packages/deye.yaml`.
4. Developer tools → YAML → Check configuration, then restart HA. The entities start with `sensor.deye_…`.

## 3. Dashboard

Settings → Dashboards → Add dashboard → open it → ✎ Edit → ⋮ → Raw configuration editor →
paste `ha/dashboard.yaml`. It has the headline, a battery gauge, phases, the plan, sun, 24/48 h graphs and
daily per-phase bars.

For an animated energy flow like the app's, install **power-flow-card-plus** from HACS and point it at
`sensor.deye_z_merezhi` (grid), `sensor.deye_sontse` (sun), `sensor.deye_batareia_potuzhnist` (battery,
+ discharge) and `sensor.deye_batareia` (SoC).

## 4. Energy dashboard

Settings → Dashboards → Energy:

| Energy dashboard field | Sensor |
|---|---|
| Grid consumption | `sensor.deye_z_merezhi_vsogo` |
| Solar production | `sensor.deye_sontse_vsogo` |
| Battery: energy going in | `sensor.deye_batareia_zariadzheno_vsogo` |
| Battery: energy coming out | `sensor.deye_batareia_viddala_vsogo` |
| Individual devices | `sensor.deye_spozhito_faza_a_vsogo`, `…_faza_b_vsogo`, `…_faza_c_vsogo` |

The totals are running sums since the first sample and never decrease. The first day in HA starts at the
current value, so HA's statistics begin from the day you add it (the app's History tab keeps the full past).

## Notes

- Entity ids come from the Ukrainian names (HA transliterates them). Renaming an entity's display name in HA is
  safe; changing its entity id breaks the dashboard. The phases are called A/B/C in HA; the app's phase names are
  in the JSON (`phase_names`) if you want to rename them in HA.
- Timestamps (`…_vidkliuchennia`, `…_siade`) are unavailable when there is nothing to show.
- 60 s polling = ~1,400 requests a day; the Worker caches the answer for 20 s.
- When the Pi stops sending, the values freeze; watch `sensor.deye_vik_danikh` (data age, s) for an automation.
